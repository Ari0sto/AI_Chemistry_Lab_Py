# AI Chemistry Lab

Учебное локальное веб-приложение для прогнозирования **водной растворимости молекул (logS)** по SMILES с использованием Hugging Face.

- **Backend:** Python, FastAPI, RDKit, Transformers, PyTorch, CSV.
- **Frontend:** React, TypeScript, Vite, Recharts.
- **Модель:** [khanfs/ChemSolubilityBERTa](https://huggingface.co/khanfs/ChemSolubilityBERTa) — регрессия на ESOL (прогноз log₁₀(моль/л)).
- **Работает локально:** интернет нужен при первой загрузке модели и установке зависимостей.

## 1. Установка на Windows

Требуются **Python 3.11 или 3.12** и **Node.js 20.19+ или 22.12+** (или более новая совместимая версия). Откройте **PowerShell**.


### Backend — один терминал

```powershell
cd D:\AI_Chemistry_Lab_Py\backend
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python -m uvicorn main:app --reload
```

Проверка API: http://127.0.0.1:8000/docs

### Frontend — второй терминал

```powershell
cd D:\AI_Chemistry_Lab_Py\frontend
npm install
npm run dev
```

Откройте http://127.0.0.1:5173

Для повторных запусков удобно открыть `start_backend.bat` и `start_frontend.bat` из корня проекта (после установки зависимостей).

> **Важно:** если проект у вас расположен в другой папке на D, измените путь в командах `cd`. API использует относительные пути к `data`, поэтому в коде менять ничего не нужно.

## 2. Как пользоваться

1. **Прогноз одной молекулы:** введите название и SMILES и нажмите «Прогнозировать растворимость». RDKit проверит структуру и вычислит формулу, Hugging Face рассчитает logS, после чего результат появится в таблице и CSV.
2. **Анализ ≥10 молекул:** нажмите «Анализировать все образцы». Из `data/molecules.csv` будут обработаны 12 заранее подготовленных соединений. Первый запрос может занимать больше времени из-за первоначальной загрузки модели; последующие используют кэш.
3. **Поиск и сортировка:** используйте поиск по названию/SMILES и выпадающий список над таблицей.
4. **Сравнение:** поставьте галочки у 2+ веществ в столбце «Сравнить»; ниже появится диаграмма.
5. **Экспериментальные значения:** при наличии проверенного источника выберите вещество, введите *экспериментальный logS* и источник/DOI. График дополнится второй серией, а интерфейс рассчитает |прогноз − эксперимент|. Данные сохраняются в `data/experimental_values.csv`.
6. **Экспорт:** кнопка «Скачать CSV» скачивает `chemistry_results.csv`.

Результаты одного и того же канонического SMILES **обновляются** при повторном анализе, а не дублируются. Формула вычисляется автоматически; название задаёт пользователь.

## 3. API

- `GET /` — статус API.
- `POST /predict` — один прогноз; тело: `{"name":"Этанол","smiles":"CCO"}`.
- `POST /predict/batch` — несколько; тело: `{"molecules":[{"name":"Этанол","smiles":"CCO"}]}` (до 30 за вызов).
- `GET /molecules` — сохранённые результаты.
- `GET /molecules/search?name=эт` — поиск.
- `GET /molecules/sort?descending=true` — сортировка.
- `DELETE /molecules/{smiles}` — удалить запись.
- `GET /samples` — исходные образцы (API преобразует `molecule_name` в `name` при отправке пакетного прогноза на фронтенде).
- `GET /experimental`, `PUT /experimental/{smiles}` — экспериментальные значения.
- `GET /export/results` — скачать CSV.

Интерактивная документация: http://127.0.0.1:8000/docs

## 4. Формат CSV

`chemistry_results.csv`:

```csv
molecule_name,formula,smiles,predicted_property,predicted_value
```

Файл **в архиве содержит только заголовок**, поскольку новые прогнозы нужно получить реальным запуском модели. После пакетного анализа он содержит ≥10 строк. **Не заменяйте этим пустым шаблоном свой CSV с ранее рассчитанными значениями** — сохраните или перенесите его при объединении проектов.

`molecules.csv` — исходные образцы `molecule_name,smiles`.

CSV кодируются `UTF-8 with BOM`, чтобы русские названия корректно открывались в Excel.

## 5. Ограничения

- Модель — исследовательский прототип, обученный на ESOL, не экспериментальный прибор.
- Прогноз `logS` не следует трактовать как надёжную физическую растворимость для любого соединения, особенно для полностью смешивающихся с водой жидкостей (этанол, ацетон и др.).
- Модель **не** предсказывает температуру кипения, токсичность или температуру плавления.
- Если SMILES невалиден, RDKit вернёт ошибку; слишком длинная токенизированная структура не обрезается молча, а отклоняется.
- Экспериментальные значения из внешних публикаций приложение не подгружает автоматически: пользователь вводит их вручную с источником.
- CSV рассчитан на локальное однопользовательское использование; для многопользовательского сервера следует использовать БД.

## 6. Возможные неполадки

- `Failed to fetch` / «Сервер недоступен» — запустите бэкенд на `127.0.0.1:8000`.
- `npm` не распознаётся — установите Node.js LTS, откройте новый терминал.
- Порт 5173 занят — остановите другой Vite-сервер (проект использует фиксированный порт).
- Загрузка модели идёт на C — проверьте значение `HF_HOME` в **том же терминале**, в котором запускается бэкенд.
- `ModuleNotFoundError` — активируйте `backend/.venv` и повторно запустите `python -m pip install -r requirements.txt`.
- Белая страница/ошибка TypeScript — проверьте консоль `npm run dev` и вкладку DevTools → Console.

Приложение локально протестировано. Все 12 проверок пройдены без обнаруженных ошибок:

- прогноз одной молекулы;
- пакетное прогнозирование 12 образцов;
- сохранение данных после перезапуска;
- поиск и сортировка;
- сравнение молекул на графике;
- добавление экспериментальных значений;
